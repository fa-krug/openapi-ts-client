# anyOf Type Extraction Design

## Overview

Extract anyOf schemas with `title` properties as separate empty interface model files to match openapi-generator behavior exactly.

## Problem

The generator currently inlines anyOf types as unions (e.g., `number | string | null`). The openapi-generator extracts titled anyOf schemas as separate model files with empty interfaces, then references them by name.

**Current output:**
```typescript
score?: number | string;
```

**Expected output (matching fixtures):**
```typescript
// score.ts
export interface Score { }

// inspectionOut.ts
import { Score } from './score';
export interface InspectionOut {
    score?: Score;
}
```

## Design

### Phase 1: Discovery

Recursively traverse the entire OpenAPI spec to find all anyOf schemas with `title` properties.

**Locations to scan:**
- `components/schemas/*` properties
- Operation parameters (query, path, header)
- Request bodies
- Response schemas
- Anywhere else in the spec

**Discovery output:**
```python
{
    "components/schemas/InspectionOut/properties/score": {
        "title": "Score",
        "schema": {"anyOf": [{"type": "number"}, {"type": "string"}]}
    },
    # ... more discoveries
}
```

### Phase 2: Name Assignment

Assign unique type names with numeric suffixes for duplicates.

**Algorithm:**
1. Sort discoveries by JSON path (deterministic ordering)
2. Track used names
3. First "Score" → `Score`
4. Second "Score" → `Score1`
5. Third "Score" → `Score2`

**Conflict resolution:**
- If title conflicts with existing `components/schemas` name, the anyOf-extracted type gets the numeric suffix

### Phase 3: Model Generation

Generate empty interface files for each extracted type.

**File template:**
```typescript
/**
 * {API Title}
 *
 * {API Description}
 *
 * NOTE: This class is auto generated by OpenAPI Generator (https://openapi-generator.tech).
 * https://openapi-generator.tech
 * Do not edit the class manually.
 */


export interface {TypeName} {
}

```

**File naming:** PascalCase type → camelCase filename
- `Score` → `score.ts`
- `Score1` → `score1.ts`
- `CodeQuality` → `codeQuality.ts`

### Phase 4: Type Reference Resolution

Modify type mapper to reference extracted types instead of inlining unions.

**Logic change in `type_mapper.py`:**
```python
if "anyOf" in schema:
    if "title" in schema:
        type_name = registry.get_type_name_for_schema(schema)
        return type_name, {type_name}
    else:
        # Existing inline union logic
        ...
```

**Import handling:**
- Add import statement for the extracted type
- Follow existing relative import patterns

## Edge Cases

| Case | Handling |
|------|----------|
| Nested anyOf with title | Extract inner titled anyOf |
| Same title, identical schema | Deduplicate to single type |
| Title conflicts with schema name | anyOf-extracted type gets suffix |
| Nullable anyOf with title | Extract as empty interface (ignore null) |
| anyOf without title | Inline as union (existing behavior) |
